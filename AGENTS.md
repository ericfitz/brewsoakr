# brewsoak

## Installing soaked formulae

- Soaked `homebrew/core` and `homebrew/cask` packages are installed from brewsoak's own local tap `ericfitz/brewsoak` (`origin::SOAK_TAP`), because Homebrew 7.0.14+ no longer loads formulae from paths (issue #17); spec: `docs/superpowers/specs/2026-11-27-local-tap-install-design.md`. `brewsoakr/soaked` survives only as `origin::STAGING_TAP` so pre-1.0 receipts and `tap-info` entries classify as staged, never as an origin (issue #4). Third-party tap packages never use the soak tap: they keep the by-name gate (`Brew::by_name`, bare names, brew's current definition byte-identical to the soaked cutoff). No-soak and unsoakable packages never use it.
- For the by-name gate (third-party packages only), hash the raw cutoff blob from `resolve_pkg_blobs`, never a staged or sanitized file and never brewsoak's HEAD blob, and use a by-name dependency list only after that package passed. Never hand brew a file path or a `user/repo/name` token for a third-party package.
- Never create the GitHub repository `ericfitz/homebrew-brewsoak` (brew would clone it and trust whatever it held). Never run `brew trust` or `brew untrust`, set `HOMEBREW_NO_REQUIRE_TAP_TRUST`, or edit brew's trust store: the user runs `brew trust ericfitz/brewsoak` once.
- Tap-ready rule: issue no command that carries `ericfitz/brewsoak/<name>` unless `SoakTap::ready` returned `Ok` in this run or `tap_state` is `Ready` (tap local, `remote: null`, and trusted; a missing `trusted` field counts as trusted). A real run creates a missing tap with `brew tap-new --no-git`; a dry run creates nothing. Any other state holds every soak-tap package with the tap-not-ready note, printed once per run.
- Tap files: the content is `tap::sanitize_unofficial` of the raw cutoff blob (drops whole `no_autobump!` stanzas only: continuation lines, a `do` block through its closing `end`, found at the first later non-blank line not indented deeper than the stanza, which closes it only when it is exactly the stanza's indentation plus `end` as a whole word; otherwise the block is unclosed, the stanza is left untouched and brew holds it; a blob without one is written byte for byte), at `Formula/<name>.rb` or `Casks/<token>.rb`. Write an undo entry in `<cache>/soak-tap-undo/{Formula,Casks}/` (`<name>.rb` with the old bytes, or an empty `<name>.absent`) first, then the file, only while holding the run lock. When a target is finished, settle every file with an undo entry: keep it when the package is installed at that version with a receipt naming the soak tap (the keg decides, not brew's exit status); the one test is `soaktap::from_tap_at` (the receipt at the file's version, or for a formula any soak-tap keg whose `.brew/<name>.rb` has the file's `file_version`); otherwise put the old bytes back. Never compare a keg directory name with a parsed version on its own. A dry run always restores.
- Verbs and tokens: a soak-tap formula that is not installed is `brew install --formula ericfitz/brewsoak/<name>`; one that is installed (from any tap) is `brew upgrade --formula ericfitz/brewsoak/<name>`; a cask is `brew install --cask ericfitz/brewsoak/<token>`. Filter user flags for the verb actually run (`flags::filter_for_verb`). Show bare names in output. Bypass hints and no-soak tokens for an anchored formula (receipt names the soak tap and its file has the installed version) are `homebrew/core/<name>`, with `brew reinstall` for `reinstall` and `upgrade` for everything else (`nosoak::official_verb`; brew refuses `install` over a soak-tap keg). A formula with a legacy receipt (it names `brewsoakr/soaked`, or the soak tap with no file at the installed version) keeps the bare token. A cask whose receipt names the soak tap, anchored or not, has no legacy rule: its hint is `brew <verb> --cask homebrew/cask/<token>`, and its no-soak token is `homebrew/cask/<token>`, with `--cask` only when a formula and a cask are both in the no-soak run.
- Dependency table: a soak-tap member's dependencies come from `brew deps --1 --full-name --formula|--cask ericfitz/brewsoak/<name>` after its file is written (that is also the load test). A missing dependency, and an installed one this run upgrades, is installed from the soak tap first, by full token. Any other installed formula dependency passes when brew's own dependency test says it is satisfied (anchored ones always are); otherwise it passes only when brew's current file is byte-identical to its cutoff, else the target is held. Cask dependencies are left alone.
- Two maintenance points touch the tap outside an install: recovery (settle leftover undo entries) when the tap is local, then pruning (remove `.rb` files with no undo entry whose package is not installed with a receipt naming the tap) when it is local and trusted. They run in `brewsoak update` and at the start of a real `upgrade`, `install` or `reinstall`; never on a dry run, `outdated`, `info` or `ensure_snapshots`. Both take the `&RunLock`. Before it removes a formula's file, pruning takes brew's formula lock (`Brew::lock_formula`, `<prefix>/var/homebrew/locks/<name>.formula.lock`) and reads the receipts again; a busy lock skips the file. Never hold that lock while a brew child runs. Casks have no brew lock.
- Holds are never fatal: a gate failure, a tap-not-ready, any `Error::Brew` from the walk, `brew deps` or `by_name` holds that one target, the next package still runs and the run exits 1. Git and I/O errors stay fatal. No hold names issue #17. A package installed from an untrusted soak tap is held, and a dependency in that state is the tap-not-ready hold, not the third-party text. An untrusted third-party tap and an ambiguous name keep their own holds; `GateWhy::ChangedSinceCutoff` says the file changed since the cutoff and installs once the change soaks. A formula brew hides because its tap is untrusted is a note (`Inventory.hidden`), never a hold or an error, and brewsoak still never runs any `brew trust` command, `--json=v1` included.
- Run one `brew update` per run, before soaked work, only when the run has soaked work (also on a dry run). Its failure is a note and an exit code, never a hold. The no-soak step repeats it only when it did not succeed.
- Set `HOMEBREW_NO_AUTO_UPDATE=1`, `HOMEBREW_NO_INSTALLED_DEPENDENTS_CHECK=1` and `HOMEBREW_NO_COLOR=1` on every brewsoak `brew` child (brew colors some `==>` lines even into a pipe; the summarizer's ANSI strip is only a fallback).
- Also remove `HOMEBREW_FORCE_API_AUTO_UPDATE` from brew children, so brew's loaders read the taps as they are.
- `HOMEBREW_FORBID_PACKAGES_FROM_PATHS` is still removed and `HOMEBREW_DEVELOPER=1` still set (`brew ruby` needs it), but neither enables path loading now. Never set `HOMEBREW_DEVELOPER` on an `update` child: it makes `brew update` follow `main` instead of the latest stable tag, so that child inherits the user's own value (`brew::brewsoak_brew_env_pairs(verb)`).
- Never pass `--ignore-dependencies`. Homebrew treats it as an unsupported developer option and warns even in developer mode. Install the cutoff dep closure first, then install the target and let brew treat already-installed deps as satisfied.
- Cellar receipts omit `bottle`/`rebuild`. Do not treat a missing rebuild as 0 when comparing installed vs cutoff.
- `-v`/`--verbose` prints the soak window, cutoffs, and a line for every package evaluated. Bare `-v` is brewsoak help, not `brew -v`.
- Persist `--soak-hours` only on soaked commands, never on passthrough/`--version`/`--help`.
- Do not uninstall a `homebrew/core` keg to switch taps.

## Origins and staging

- A package's origin is its receipt tap when it is non-empty and not `brewsoakr/soaked`: for a formula, `source.tap` in the keg's `INSTALL_RECEIPT.json` (never `brew info`'s top-level `tap`, which is where brew resolves the name now and says `homebrew/core` for a staged tap keg that shares a core name); when a formula's `source.tap` is null and `source.path` is under `<cache>/staging/taps/<user>/<repo>/`, the origin is `<user>/<repo>`; for a cask, `tap` from `brew info --json=v2 --installed`; else `<cache>/origins.toml` (`"formula:<name>" = "user/repo"`); else `homebrew/core` / `homebrew/cask`. A by-name install of a tap package records its tap in the receipt, so remove the origin record after every real by-name or soak-tap install (not on a dry run, not on brew's "already installed" answer about the package or its "Not upgrading <name>, ..." line, and not for a core or cask target none of whose receipts names the soak tap). `<cache>/staging/` is still read (old receipts with a null tap and a staged `source.path`) but no longer written.
- The dependency walk runs `brew deps --1 --full-name`: brew resolves bare dep names (core first, then a unique installed tap) and prints `user/repo/name` for tap packages, so a full name is that tap and a bare name is core or cask. An ambiguous name (`TapFormulaAmbiguityError`) holds the target.
- `<cache>/staging/` (`taps/<user>/<repo>/{Formula,Casks}/<name>.rb` for tap packages, directly under it for core and cask) is historical: brewsoak no longer writes it, but old receipts may still point into it.
- Tap history lives in `<cache>/taps/<user>/<repo>.git`: a bare clone with a named `origin` remote, fetched `--filter=blob:none` (retry without the filter if the server rejects it). Never fetch into, or move the checkout of, anything under `$(brew --repository)/Library/Taps`; the one exception is writing and deleting `.rb` files under `Formula/` and `Casks/` of `ericfitz/brewsoak`, while holding the lock. No GitHub API calls for taps.
- `NO_SOAK` packages go to brew as full tokens (`user/repo/name` for tap packages) in one `brew upgrade|install|reinstall` after all soaked work (preceded by `brew update` unless one already succeeded). A no-soak package whose keg was staged by brewsoak is moved to its real tap with `brew install user/repo/name`.
- `brew tap-info --json --installed` reports `remote: null` for API-mode `homebrew/core` and `homebrew/cask` and for a leftover `brewsoakr/soaked` tap; classify those by name before applying the "no HTTPS remote = unsoakable" rule.
- A tap whose fetch fails holds only that tap's packages (`Error::Git` note). Core or cask fetch failure still aborts the run.
- Config: top-level keys (`SOAK_HOURS`, `NO_SOAK`) must precede the first `[[TAP]]` table in every example; a `NO_SOAK` inside `[[TAP]]` is ignored with a stderr warning.

## Output

- `--formula`/`--cask` restrict a bare `upgrade`, `outdated` and `info` (`flags::kind_filter`); filter the walk, never the `Inventory`.
- Every byte of `brew` output goes to the per-run log under `$TMPDIR`; the terminal gets a summary. Never suppress a line without logging it.
- Visible `brew` runs share one pipe for stdout and stderr so the summarizer sees them in the order brew wrote them. `Output.stderr` is empty for visible runs; callers must read `Output.stdout`.
- Unrecognized brew lines pass through verbatim (minus the `==>` marker). The filter is a summarizer, not an allowlist: never swallow the unknown.
- `--raw` must always be able to turn the summarizer off.
- The installed snapshot is taken once and goes stale as soon as brew upgrades a dependency for us. Compare against what brew reported installing (`quiet::installed_from_output`) before spawning another `brew install`.

## Git

- Every git invocation goes through `ProcessGit` / `GitStore` in `src/git.rs`. Do not spawn `git` from other modules.
- Soak refs (`refs/brewsoak/cutoff`, `refs/brewsoak/head`, `refs/brewsoak/window`) are pins, not branches. Updates must force (`+sha:ref` and `git fetch --force`). Never assume a fast-forward.
- Trap every git failure. Surface `Error::Git` with:
  - `action`: what brewsoak was doing, in our words
  - `detail`: git's stderr (or why git could not start)
- Do not leak a raw git message as the only user-visible text.

## Cache state

- Commands that write the cache (`update`, `upgrade`, `install`, `reinstall`) hold the `<cache>/run.lock` flock from the start of `dispatch` (`lock::LockSlot`). `outdated` and `info` start unlocked; `cmd::ensure_snapshots` takes the lock itself when it finds the snapshot missing, unreadable or stale, then re-reads `state.toml` and decides again. Code that writes `state.toml`, the clones, gc or prune takes a `&RunLock`; never write the cache without one. The holder's pid and command live in `run.lock.holder` (temp + rename). `settings` never touches the cache.
- After a refresh, `prune::prune_cache` (under the lock) removes clone and staging dirs of taps no longer tapped and `origins.toml` records of packages no longer installed. Never prune a record because its tap is gone while the package is installed; brew's installed list can lack an installed formula (`Inventory.unlisted_formulae`), and its origin record is kept; never touch `$(brew --repository)/Library/Taps` except the `.rb` files under `Formula/` and `Casks/` of `ericfitz/brewsoak`.
- Write `state.toml` and `origins.toml` only through `atomic::write` (temp + rename, then fsync the directory).
- `gc_prune` runs only after `state.toml` is written.
